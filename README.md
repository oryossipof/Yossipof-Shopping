# 🛒 רשימת קניות — PWA

אפליקציית רשימת קניות משפחתית. עובדת כאפליקציה מותקנת באנדרואיד ובאייפון, בלי חנויות אפליקציות ובלי עלות.

**האפליקציה כבר לא תלויה ב-Lovable.** אפשר לערוך אותה בכל עורך קוד, לבנות אותה ולפרסם אותה בעצמכם.

---

## מה השתנה מהגרסה המקורית

| | לפני | אחרי |
|---|---|---|
| מסגרת | TanStack Start (SSR) | Vite + React (SPA) |
| אחסון | Cloudflare Workers | כל אחסון סטטי חינמי |
| סיווג מוצרים | AI דרך שער של Lovable | מילון עברי מקומי — מיידי, חינמי, עובד בלי אינטרנט |
| התקנה בנייד | לא | ✅ PWA מלא |
| בלי אינטרנט | מסך שגיאה | מציג את הרשימה השמורה |

התלות ב-Lovable הוסרה לחלוטין. מסד הנתונים (Supabase) נשאר.

---

## הפעלה מקומית

צריך [Node.js](https://nodejs.org) גרסה 20 ומעלה.

```bash
npm install
cp .env.example .env      # ואז מלאו את הערכים
npm run dev
```

האפליקציה תיפתח בכתובת `http://localhost:5173`.

לבנייה לייצור:

```bash
npm run build             # התוצאה נכנסת לתיקיית dist/
npm run preview           # בדיקה מקומית של גרסת הייצור
```

## הגדרת מסד הנתונים

אם אתם עוברים לפרויקט Supabase משלכם (מומלץ — חינמי, 500MB):

1. פתחו חשבון ב-[supabase.com](https://supabase.com) וצרו פרויקט חדש
2. **SQL Editor** → **New query** → הדביקו את התוכן של `supabase/setup.sql` → **Run**
3. **Project Settings → API** → העתיקו את `Project URL` ואת המפתח `anon public`
4. הכניסו אותם לקובץ `.env`:

```
VITE_SUPABASE_URL="https://xxxxx.supabase.co"
VITE_SUPABASE_PUBLISHABLE_KEY="eyJhbGci..."
```

> ⚠️ **הערה על אבטחה:** הכניסה לאפליקציה היא לפי מספר טלפון בלבד, בלי אימות SMS.
> ההרשאות במסד הנתונים פתוחות בהתאם. לרשימת קניות משפחתית זה בדרך כלל בסדר,
> אבל כדאי לדעת: אין כאן הגנה אמיתית על הנתונים. פירוט ב-`supabase/setup.sql`.

## פרסום לאינטרנט (חינם)

צריך **HTTPS** כדי ש-PWA יעבוד. כל האפשרויות למטה נותנות אותו אוטומטית.

### Netlify — הכי פשוט

1. העלו את הפרויקט ל-GitHub
2. [netlify.com](https://netlify.com) → **Add new site** → **Import an existing project**
3. בחרו את ה-repo. ההגדרות ייקראו אוטומטית מ-`netlify.toml`
4. **חשוב:** לפני הפרסום, **Site settings → Environment variables** → הוסיפו את
   `VITE_SUPABASE_URL` ו-`VITE_SUPABASE_PUBLISHABLE_KEY`
5. **Deploy**

### Vercel

אותו תהליך; ההגדרות נקראות מ-`vercel.json`. אל תשכחו את משתני הסביבה.

### Cloudflare Pages

Build command: `npm run build` · Output directory: `dist`

> אם אחרי הפרסום מופיע מסך "האפליקציה לא נטענה" — כמעט תמיד שכחתם להגדיר את
> משתני הסביבה, או שהגדרתם אותם אחרי הבנייה ולא בניתם מחדש.

### אנדרואיד (Chrome)

```ts

"טחינה": "spices-canned",
```

## העברת הנתונים למסד החדש

בתיקיית `tools/` נמצא הקובץ `ייצוא-לSQL.html`.

פותחים אותו בדפדפן (לחיצה כפולה), לוחצים על **"שלוף את הנתונים"**, ומקבלים
פקודות SQL מוכנות להדבקה ב-SQL Editor של הפרויקט החדש. פרטי החיבור למסד הישן
כבר מוטמעים בקובץ — אין מה להגדיר.

הפקודות בטוחות להרצה חוזרת: שורות שכבר קיימות ידולגו.

> חלופה למי שמעדיף שורת פקודה: `node migrate.mjs backup` ואז `restore` ו-`verify`.
> דורש Node.js 18+ ואינו דורש התקנת חבילות.
